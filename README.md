# BC-SHIELD

**Blockchain-Enabled Federated Learning for Privacy-Preserving Intrusion Detection in Distributed IoT Networks**

BC-SHIELD is a research implementation accompanying the manuscript:

> **A Blockchain-Enabled Federated Learning Framework for Privacy-Preserving Intrusion Detection in Distributed IoT Networks**

The framework combines **Federated Learning (FL)**, a lightweight CNN, **Differential Privacy (DP)**, adaptive reputation-based Byzantine defense, **Hyperledger Fabric**, IPFS, and smart-contract-driven threat response for distributed IoT intrusion detection.

> **Reproducibility note:** this repository does **not** hard-code manuscript results. Metrics are generated by actual experimental runs and can be compared with the manuscript targets using `scripts/verify_against_paper.py`.

---

## Key Features

- Lightweight depthwise-separable CNN for IoT intrusion detection
- Knowledge distillation with teacher–student training
- INT8 post-training quantization
- Federated learning with non-IID Dirichlet partitioning
- Whole-client-update L2 clipping and Gaussian differential privacy
- Rényi Differential Privacy (RDP) accounting
- Cosine-similarity Byzantine update detection
- Adaptive reputation-based aggregation
- Reputation recovery and probation for excluded clients
- Model poisoning, label flipping, random-noise, and Sybil attack evaluation
- Membership inference and gradient inversion privacy evaluation
- Hyperledger Fabric + IPFS integration
- Smart-contract-based reputation, Byzantine voting, and threat response
- Baseline implementations for FedAvg, HBFL, BFLIDS, FedIoT, FLTrust, FoolsGold, Krum, and Trimmed Mean

## Datasets

The repository supports:

1. **CICIoT2023**
2. **Edge-IIoTset**

Place datasets under:

```text
data/ciciot2023/
data/edge_iiotset/
```

or use:

```bash
bash scripts/setup_dataset.sh --dataset ciciot2023
bash scripts/setup_dataset.sh --dataset edge_iiotset
```

### Preprocessing policy

To avoid data leakage:

1. The dataset is split into train/validation/test partitions.
2. Median imputation and standardization statistics are fitted on the **training partition only**.
3. The same fitted preprocessing parameters are applied to validation and test data.
4. Only training data are distributed among federated clients.

## Reproducibility and Scientific Transparency

The repository separates three concepts:

1. **Manuscript-disclosed settings** — implemented directly where sufficiently specified.
2. **Measured outputs** — produced by actual runs.
3. **Reported manuscript targets** — stored separately in `paper_targets.json` for comparison.

No manuscript metric is injected into the training process.

Some manuscript specifications are internally difficult to reconcile exactly from the text alone, particularly the simultaneously stated CNN parameter/model-size values. These issues are documented in:

```text
PAPER_ALIGNMENT.md
```

Users should review that file before interpreting small or large deviations from manuscript results.

Exact numerical reproduction can also depend on:

- dataset release/version,
- library versions,
- hardware,
- random seeds,
- GPU determinism,
- federated client sampling,
- DP-noise sampling,
- and implementation details not fully specified in the manuscript.
